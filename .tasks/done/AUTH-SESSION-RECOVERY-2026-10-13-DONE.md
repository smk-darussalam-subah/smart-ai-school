## Implementation

- Shared Edge-safe lifecycle: valid credentials, terminal vs temporary failure,
  proactive refresh at ten minutes, retry backoff 30 seconds and five-minute
  client polling. Existing eight-hour web session policy is unchanged.
- Validated provider responses and bounded in-process single-flight/replay;
  rejected credentials are cleared, expired access is never exposed as usable.
- Installed NextAuth request/response serializer persists updated/chunked cookies
  in writable route/proxy boundaries. Refreshed cookies survive a subsequent
  upstream connection failure. No mutation is replayed after an upstream result.
- Recovery stays reachable despite stale cookies. Redirect origin comes from
  trusted `NEXTAUTH_URL`, never an internal service port or spoofed Host header.
- Initial sign-in checks `/api/v1/auth/me` and rejects unavailable account access
  on 401/403. Client session update data cannot replace identity/roles/tokens.
- Dashboard permission loading failure is an unavailable/retry surface, not a
  healthy empty dashboard or an inferred permission revocation.
- Client hooks are unconditional. Definitive rejection or identity change leaves
  the old workspace. Transport-null sessions remain on a recovery notice with
  the workspace mounted until explicit reload; reload warns about unsaved input.
  NextAuth v4 `update()` is not called as a supposed fix for a null session.
- Existing DIIS compact typography and emerald palette are retained; touch targets
  are at least 44px, keyboard usable and mobile layout has no horizontal overflow.
